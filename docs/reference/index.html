Architecture and execution boundaries

The installed distribution contains bcla* and exposes the bcla console command. Native analysis uses NumPy, SciPy and Matplotlib. Checkout-only examples, data, notebook and static Pages assets are separate working surfaces. There is no model server, database or browser-to-Python execution bridge in this source. pyproject.toml:5–17 pyproject.toml:54–58 docs/index.html:155–162

Native analysis flow

  1. datasets produces seeded synthetic traces, reads a single-cell CSV/TSV, or loads a long-form table with per-cell metadata and optional interval history.
  2. core receives numerical cycle and capacity arrays. The direct fitter does not normalize or sort them; temporal validation sorts by cycle and keeps duplicate cycle groups together.
  3. Late-cycle validation chooses a family, then select_model_by_validation refits that family to all observations. best_model instead selects by an in-sample diagnostic.
  4. FitResult stores arrays, parameters, covariance and fit diagnostics. EOL scans a finite grid; the bootstrap refits one selected family and withholds bounds after any failed or censored replicate.
  5. viz returns Matplotlib objects; the CLI writes bcla_demo.png in the current working directory. bcla/datasets.py:653–923 bcla/core.py:179–404 bcla/core.py:407–533 bcla/main.py:74–178

Metadata such as temperature, C-rate, protocol, timestamps and duty-cycle intervals is preserved and summarized by loaders. It is not automatically a regressor or damage accumulation input to the capacity-fade functions. Keep the observation table and provenance beside the arrays. bcla/datasets.py:206–262 bcla/datasets.py:746–923 bcla/core.py:179–241

Troubleshooting

Symptom Source-supported explanation and next check
Initial guess outside bounds / implausible fit Fitter expects normalized-capacity scale through Q0∈[.5,1.5]; it does not normalize input. Check units, first-row denominator, q0_guess and family bounds. --no-normalize is not unit conversion.
Too few training/distinct cycles Validation needs four distinct early cycles and two distinct late cycles. Its fraction counts rows and duplicates move the split. Reduce holdout fraction only if a scientifically meaningful split remains; a three-row metadata fixture cannot satisfy this contract.
Constant-series R² confusing Training R² is 0 when total variance is zero; held-out R² is NaN. R²-based selection rejects nonfinite scores. Report RMSE and data variation instead of treating NaN as a good score.
eol_cycle returns None No threshold crossing in 0..3 max(cycles). This is a bounded unavailable estimate, not infinite life.
Negative project output project has no finite search horizon or nonnegative-capacity clamp. Check the requested range and empirical model validity.
Bootstrap interval unavailable Inspect requested/successful/censored/failed counts. A single censored or failed replicate withholds all bounds. Zero residual variance or insufficient residual degrees of freedom raises instead.
Unicode parameter key mismatch Power-law parameters are stored as α and β; use these keys. ASCII summary changes display text only.
Missing or mixed-cell loader result Simple loader expects exact headers; long-form requires cell IDs. Select for_cell explicitly; single-cell aliases reject multiple cells.
Unexpected normalization Simple loader uses first row; long-form uses earliest cycle per cell. Keep the raw source and normalization reference.
Timestamp comparison failure Mixed naive/aware ISO timestamps can be incomparable; standardize their time basis before loading. No overlap or calendar-aging model is inferred from timestamps.
EFC differs from another integrator Check positive-current sign convention, seconds/Ah conversion, first measurement origin and clipping-before-interpolation. Queries outside measured time range are rejected.
Oxford example cannot download Verify the allowed Oxford origin, file ID, network access and ≤32 MiB response; do not bypass the source host/redirect policy. Offline fixtures are a separate check.
Plot is missing or overwritten CLI writes current-directory bcla_demo.png; use a writable isolated working directory and Agg for headless execution.
Browser and Python disagree They implement different models and input contracts. The browser's degradation proxy is not a wrapper around SciPy fits.
Documentation CI passes but a nested link is broken Current Lychee arguments cover README, CONTRIBUTING and docs/*.md, not all nested handbook pages. Run the local handbook link/renderer checks and review new paths.

The validation route flattens arrays, stably sorts by cycle, and starts with max(2,⌈Nv⌉)\max(2,\lceil Nv\rceil) late rows for requested fraction vv. Oxford grid-battery real-data example

This opt-in example applies the bcla workflow to the University of Oxford's energy-trading battery degradation dataset. The source contains one year of operation for six 16 Ah lithium-ion cells following three grid-trading control strategies, with per-cell current profiles and 13 capacity checks per cell.

The repository does not bundle, mirror, or relicense the dataset. The example downloads original files from the Oxford Research Archive at runtime. Each download is capped at 32 MiB before decoding; the largest official profile was 8.87 MiB during the 2026-08-31 audit. A larger response is rejected rather than read into memory without a bound.

Converting measured current to EFC

The capacity files report profile_time_s and capacity_Ah; they do not report a laboratory cycle index. Relabeling elapsed time as cycle count would be misleading. The example instead aligns each capacity check with its cell's measured time_s,current_A profile and estimates cumulative discharge equivalent full cycles:

EFC(t) = integral(max(I(t), 0) dt) / (3600 * Q_nominal)

Positive current is discharge in the source data, negative current is charge, and Q_nominal is the stated 16 Ah cell capacity. Charging samples are clipped to zero before trapezoidal integration. The result is discharge-throughput EFC, not elapsed days, commanded cycles, or a count of laboratory charge/discharge procedures.

The official files contain a small number of duplicate or reversed profile-time rows. The example makes its repair observable: it stable-sorts profile time, averages current at identical timestamps, and prints the number of affected transitions and duplicate samples. Each final capacity check also trails the last near-zero-current sample by less than 1,004 seconds. The example caps that small tail to the last observation only when the gap is at most 1,800 seconds and the last absolute measured current is at most 1 mA; it prints the gap. Only that single final capacity check may be capped. Anything outside those conditions is rejected.

Saved figures relabel the horizontal axis as Measured Discharge EFC; they do not present this throughput estimate as a laboratory cycle count. Solid lines cover the observed window and dashed lines show only the bounded projection to EOL, or to the three-times-observed limit when EOL is unsupported. The console output states the chronological training/holdout sizes and reports bounded EOL, RUL, and bootstrap censoring diagnostics explicitly.

Contributing

Thank you for helping improve Battery Cycle-Life Analyzer. Focused changes that make the models easier to inspect, validate, or use with real cycling data are especially welcome.

Before you start

  • Search existing issues and pull requests before opening a duplicate.
  • Open an issue before a large API change or a new degradation-model family.
  • Do not include confidential, proprietary, or personally identifiable data.
  • Only contribute datasets that you have the right to redistribute, and document their source, chemistry, protocol, units, and license.

Development setup

Fork and clone the repository, then create an isolated environment:

python -m venv .venv

Activate it on Linux or macOS:

source .venv/bin/activate

Or on Windows PowerShell:

.\.venv\Scripts\Activate.ps1

Install the project and development dependencies:

python -m pip install --upgrade pip
python -m pip install -e ".[dev]"

Make a focused change

  1. Create a branch from the latest main.
  2. Keep model equations, bounds, assumptions, and units explicit.
  3. Add or update tests for behavioral changes.
  4. Update the README or docstrings when the public API or interpretation changes.
  5. Avoid committing generated figures, build artifacts, or private datasets unless they are intentionally part of the documentation.

Verify the change

Run the complete test suite:

python -m pytest -v

For changes that affect the command-line demo, also run:

python -m bcla --model all

The GitHub Actions workflow repeats the tests on all supported Python versions.

To regenerate the README and Pages comparison preview from the same 1,000-cycle synthetic NMC example (seed 7), run:

python -m examples.render_model_preview

Inspect docs/model_comparison_preview.png before committing a visual change. The Python 3.12 CI job also uploads this render as the model-comparison-preview artifact for review.

Pull requests

In the pull-request description, explain:

  • the engineering or user problem being addressed;
  • the chosen approach and any new assumptions;
  • how the result was verified;
  • any compatibility, numerical, or data-provenance considerations.

Keep pull requests small enough to review. Maintainers may ask that unrelated changes be split into separate submissions.

Reporting problems

For numerical or model-fitting problems, include a minimal reproducible example with:

  • Python and dependency versions;
  • the selected model and parameter settings;
  • a small non-confidential data sample or synthetic reproducer;
  • expected and observed behavior;
  • the complete error message, if applicable.

Please do not use the issue tracker for battery-safety decisions. Consult a qualified battery engineer and the cell manufacturer's documentation for safety-critical work.
