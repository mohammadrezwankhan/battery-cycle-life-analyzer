# Security and responsible reporting

This repository provides local scientific tooling and static teaching pages. Its model results are empirical/synthetic under documented assumptions; no BMS, pack-protection or operational safety assurance is established by passing software checks. [Scientific limits](docs/math-and-physics/ASSUMPTIONS_AND_LIMITS.md).

## Reporting

For a suspected vulnerability, use the repository's private security-advisory reporting route **if it is enabled**, or arrange a private channel with the repository owner before sharing sensitive detail. No dedicated security inbox, response SLA or supported-version policy is declared in the pinned source; do not treat a package author's no-reply address as a monitored incident inbox. The owner identity is available in the existing [citation metadata](CITATION.cff) and [repository](https://github.com/mohammadrezwankhan/battery-cycle-life-analyzer).

A useful report includes the affected immutable revision, component, minimal permitted reproduction, impact, actual output and relevant environment. Keep credentials, unpublished measurements and exploit-sensitive data out of public issues. Ordinary numerical questions and documentation defects can use a public issue with non-sensitive fixtures.
